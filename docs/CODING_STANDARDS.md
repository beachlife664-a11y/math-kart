# 代码编写与修改规则

这些规则用于保持当前版本可复刻、可测试、可维护。新修改必须遵守；不要让测试或文档依赖个人电脑路径。

## 1. 工程与依赖

- TypeScript + React + Vite + Three.js；ES 模块，路径别名 `@` 指向 `src/`。
- 新依赖必须有明确用途并写入 `package.json` / lockfile；禁止通过本机全局包或隐式脚本维持运行。
- 运行脚本只使用仓库相对路径。禁止提交 `/Users/...`、`C:\...`、个人 Skill 目录、会话目录或临时下载地址。
- 禁止提交 API Key、OAuth 数据、签名 URL、账号信息、本地轨迹或 `.env` 真实值。
- 运行时资源放在 `public/`，通过同源相对 URL 加载；正式游戏不能依赖 Hyper3D、CDN 或音频生成接口。

## 2. 代码组织

- `raceSimulation.ts` 拥有竞速状态、固定时间步、自动走线、答题、道具、碰撞和排名。
- `GameEngine.ts` 负责渲染循环、输入、镜头、车库、模型同步、音频事件与 QA 钩子。
- `world.ts` 负责环境和模型实例整合；`track.ts` 拥有赛道几何与采样；`roadKit.ts` 负责道路模块。
- `driver.ts`、`showroom.ts`、`nature.ts`、`vfx.ts`、`audio.ts` 各自保持单一职责。
- UI 只消费快照和发送明确意图，不复制竞速规则。
- 避免在渲染热路径创建大量临时对象；共享几何、材质和矩阵。

## 3. 确定性与时间步

- 竞速模拟固定 60 Hz；渲染帧率不能改变比赛结果。
- 所有玩法随机数使用项目 seeded RNG；新增 gameplay/effect 逻辑不得直接调用 `Math.random()`。
- 视觉动画使用累计游戏时间；镜头、反馈与真实渲染 delta 的关系必须明确。
- 页面失焦、暂停和重开不得造成大步长穿透、音频叠加或状态跳跃。

## 4. 自动驾驶与答题

- 默认只接受答案、暂停、静音和车库输入，不重新加入方向键、油门或手机转向按钮。
- 多行车线必须同时考虑跟车、侧向空间、弯道、障碍和奖励路线；车辆分离不能依靠互相穿过。
- 答对必须有实际状态变化：速度、能量、道具、路线或名次，不只是视觉提示。
- 答错不停车、不倒退、不额外扣速；所有赛车必须能够完赛。
- 对手强化需要预告；橡皮筋不能抹掉认真作答优势。

## 5. 碰撞与物理

- 当前采用自定义街机竞速模拟，不为“看起来高级”引入不必要的刚体引擎。
- 路障使用简化触发体；禁止对高精视觉 GLB 做逐三角碰撞。
- 无护盾碰撞为短暂减速并自动恢复，不能造成软锁；护盾抵挡不减速但消耗护盾。
- 视觉 mesh 与碰撞代理分开维护。修改车辆尺寸、路障位置或赛道时必须更新触发体和专项测试。

## 6. 模型、场景与镜头

- 新 GLB 必须检查三角面、贴图、尺寸、枢轴、朝向、落地和独立预览，再进入游戏。
- 桌面与手机 LOD 分开；重复环境使用 `InstancedMesh` 或共享几何/材质。
- 赛道、护栏、桥梁和地形保持连续支撑关系，不允许悬空、穿模或道路断裂。
- 岩石和大型环境模型除了检查摆放参数，还必须检查**变换后的实际包围盒**。
- `cliff` / `hill` 的道路净空规则：以 385 个赛道采样点、道路中心 9 米水平安全区和车辆垂直空间过滤侵入实例。
- 镜头避让是第二层保护，不能用来掩盖物体本身占道。验收必须包含真实比赛画面，不能只拍固定机位。
- 不用高精模型替代可玩的道路或碰撞逻辑。

## 7. 渲染与性能预算

| 项目 | 桌面起始预算 | 手机起始预算 |
|---|---:|---:|
| Draw calls | 300 | 150 |
| Triangles | 750,000 | 300,000 |
| Geometries | 300 | 200 |
| Textures | 60 | 40 |

- 图形修改后必须重新记录活动比赛中的 renderer 数据，不能只测车库或静态菜单。
- 超预算时先优化重复资产、LOD、实例化和贴图，不得修改断言掩盖问题。
- 手机至少验证 390×844 视口、真触摸仿真、横竖屏切换、安全区和答案按钮可达性。

## 8. 音频

- 使用分组音频管理，不在多个组件里随意 `new Audio()`。
- 音频在用户手势后解锁；BGM 跨场景切换，暂停/重开/dispose 不叠加循环。
- 高频事件使用阈值穿越和冷却，不逐帧触发；当前漂移音冷却 2.8 秒。
- 音频加载失败不能阻塞比赛；诊断必须区分“文件已加载”和“事件采样确实播放”。
- 修改音频后检查静音、暂停、继续、重开、页面失焦与解码错误。

## 9. UI 与可访问性

- 数字键、清空、退格和确认具备真实按钮语义；P1 主键盘与 P2 小键盘必须路由到各自输入，不使用只有视觉按下状态的 div。
- 处理 pointer release、cancel、capture 丢失和窗口失焦，车库拖动不能卡住。
- HUD 不遮挡关键比赛视野；文本不裁切，按钮触控面积和安全区可用。
- 保留减少动态效果支持；不用强烈抖动或全屏闪光隐藏下一步操作。

## 10. 测试与提交门槛

窄修改至少运行受影响检查；共享竞速、场景或资源修改运行：

```bash
npm run verify:assets
npm run lint
npm run build
npm run prepare:preview
npm run verify:local
```

发布前额外运行 `npm run verify:local -- --full-race`。

- 测试必须通过真实输入证明玩法，不得只靠 `setState` 跳关。
- 截图像素通过不代表美术质量或玩法正确；必须目检活动比赛与动态录像。
- 不用旧 Run ID、旧报告或旧录像冒充新代码证据。
- 文档中的数据、路径和命令必须与当前代码一致。
