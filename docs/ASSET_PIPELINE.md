# 建模与资源生产管线

## 1. 精确复刻与再生成

当前正式游戏直接加载 `public/` 中已经验收的 GLB、纹理和缩略图。**复刻不需要重新生成模型。** 原始模型、参考图、任务 ID 与优化版本随仓库保留，便于检查和二次创作。

真实生成提示词与参数位于 `assets/generation-log.json`：包含 32 条图像请求、49 次 Hyper3D 生成请求和 22 次音频请求，保留采纳、重试与被否决的迭代；不包含签名 URL、密钥或本机路径。最终采用状态以各 `asset-jobs.json` 和 `public/` 为准。

## 2. 统一美术方向

- 玩具海岛卡丁车：圆润比例、清楚轮廓、奶油白、珊瑚橙、海青和鲜亮草地。
- 近景看结构，中景看地标，远景看海岛规模；不用随机堆放高面数模型代替美术。
- Hyper3D 负责赛车和高价值地标；Three.js 负责连续赛道、地形、护栏、支撑、海水、天空、植被与 VFX。
- 重复资产使用统一模块尺寸和实例化；视觉 mesh 与碰撞代理分离。

## 5. 原模检查清单

1. 完整轮廓与背面可读，不裁切、不空壳。
2. 材质和贴图完整，无缺失纹理、错误透明或不可接受穿插。
3. 尺寸、枢轴、正面方向和底部支撑明确。
4. 车辆四轮胎与座椅完整；地标入口/通道净空满足玩法。
5. 独立渲染预览通过后才制作正式 LOD。
6. 进入游戏后再次检查车库正面、真实侧后方和比赛后方视角。

## 6. 减面与贴图优化

项目内脚本：

```bash
node scripts/decimate-glb.mjs input.glb output.glb 40000
python3 scripts/compress-glb-textures.py input.glb output.glb 1024
node scripts/preview-glb.mjs input.glb preview.png
```

- `decimate-glb.mjs` 使用 meshoptimizer，保留 UV/法线感知误差；不能用目标数字掩盖轮廓破坏。
- `compress-glb-textures.py` 需要 Python 3 + Pillow；颜色贴图使用有损 WebP，法线使用无损 WebP。
- 预览脚本和捕获脚本的具体参数以文件顶部 usage 为准。
- 手机 LOD 不是简单删除细节：优先保留轮廓、入口、轮胎、车窗和识别色。

## 7. 游戏内整合规则

- `public/models/manifest.json`：七车桌面/手机路径与整体式方向盘标记。
- `landmarks*.json`：地标目标高度、最大宽度、旋转和局部缩放。
- `environment*.json`：船、棕榈、岩体与山体配置。
- `assets.ts` 负责加载、尺寸/朝向、材质和 LOD；`world.ts` 负责槽位与实例化。
- 重复岩石执行实际包围盒道路净空过滤；侵入道路中心 9 米安全区的 `cliff` / `hill` 实例不渲染。
- 修改 `public/` 后必须重新生成运行哈希并执行 `npm run prepare:preview`。

## 8. 程序化资源范围

赛道横拱、米制 UV、路缘、标线、护栏、桥墩、主缆、吊索、集装箱底座、地形高度场、海水、云、植被、驾驶员分件、尾焰、轮胎痕迹和护盾由代码构建或组合。这样可以让碰撞、支撑、路面连续性和性能保持可控，不把整个赛道交给不可控的一次性模型。

## 9. 重新生成的边界

生成模型存在随机性，即使提示词相同也不保证与当前 GLB 一致。任何新模型进入 `public/` 前都必须重新执行原模检查、LOD、游戏内装配、完整比赛和桌面/手机预算验收；不得直接把生成结果当作已验证替换。
