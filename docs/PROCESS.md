# 制作过程与关键决策

本文件是当前版本的制作主线。更长的历史状态记录保留在 `artifacts/game-progress.md`，玩法设计见 `artifacts/design-brief.md`，美术方向见 `artifacts/v4-art-direction.md`。

## 1. 核心玩法：先证明只答题也能比赛

最初建立 Three.js 自动卡丁车核心循环：五台尺寸相近的赛车、一条连续赛道、自动加速和最终排名。随后根据反馈取消方向键和手机转向按钮，把驾驶统一为自动跟车、找空位、侧向超车、避障、弯道漂移和出弯回正。

核心契约固定为：玩家只点击小学数学答案；答对获得即时喷射、连对能量、自动道具和路段奖励；答错显示答案但不停车、不倒退。测试必须用真实答案按钮完成两圈，不能用跳关钩子代替。

## 2. 五段完整旅程

一条赛道被扩展为海滨发车区、彩色港口、山崖盘山道、水晶洞穴和跨海大桥。重点不是增加随机道具，而是高差、弯道节奏、视线变化和地标识别。四个路段分别加入港口加速线、山崖内侧捷径、水晶高速护盾线和落地冲刺。

## 3. 美术从程序原型升级为统一资产管线

早期场景暴露基础几何感、比例失调和风格不统一。后续采用统一玩具海岛方向，并建立“参考图 → Hyper3D → 原模检查 → LOD → 游戏校准”管线。

- v3：港口主楼、渔船、岩体、洞穴、桥塔、棕榈和灯塔等地标资产。
- v4：赛道横拱、PBR 路面、护栏、植被、水面、驾驶员和场景支撑结构。
- v5：赛车与环境统一为圆润奶油白/珊瑚橙/海青卡通风格。
- v6：七款轮廓明显不同的独立赛车，桌面约 40k、手机约 14k 三角面；建立真实三维车库。
- v7：首屏改为赛车控制台，七张缩略图均由正式 GLB 渲染，保证每辆车完整可见。
- v8：逐车修正驾驶员坐姿与手臂锚点，修复大桥、集装箱、吊机和底座支撑；山体统一为已确认的玩具海岸坡崖变体。

真实提示词、任务参数和模型来源见 `assets/generation-log.json` 与各 `artifacts/art-v*/asset-jobs.json`。

## 4. 音频与碰撞反馈

v9 加入车库/比赛双 BGM 和按钮、答题、加速、碰撞、漂移、倒计时、冲线、预告等独立音效。原始母带保存在 `assets/audio/seed/`，运行文件保存在 `public/audio/`。落地和引擎因生成服务容量限制继续使用合成音。

路障从“自动驾驶绕开但无碰撞反馈”升级为真实触发：无护盾速度乘 0.58、最低 7、约 0.9 秒恢复；护盾抵挡不减速但消耗护盾。漂移音使用阈值穿越和 2.8 秒冷却。

## 5. 挡路岩石问题：一次重要的验收纠错

曾通过固定机位和参数外移判断道路已经清空，但用户再次指出两块大石头。随后在当前 v9 的真实答案输入比赛中复现第二圈山崖和洞穴遮挡，证明旧结论不充分。

QA 增加相机中心射线审计，山崖故障时命中：

1. `hyper3d-instanced-hill` 实例 4；
2. `hyper3d-instanced-hill` 实例 2。

修复不再只挪模型或推镜头，而是在实例化时检查实际几何包围盒：385 个赛道采样点、道路中心 9 米水平安全区、车辆垂直空间；侵入的 `cliff` / `hill` 实例不渲染。过滤后原故障时间点中心首命中均为道路，完整两圈录像也重新验收。

这一教训已写入编码规则：**固定截图、摆放参数和镜头避让不能替代真实比赛中的物体净空验证。**

## 6. 当前 v9 基线

- 最新完整比赛 20 次答对、7 次超车、0 软锁、0 浏览器错误，动态峰值 203 calls / 666,668 triangles。

详见 `artifacts/final-evidence.md`。

## 7. 复刻仓库整理

最终仓库补充了原项目没有的可移植性能力：Node 静态服务器、跨平台一键安装、一键验证、运行资源 SHA-256、仓库内画布检查器、GitHub Actions、完整文档和生成日志。构建与测试不再引用个人电脑上的绝对路径。
